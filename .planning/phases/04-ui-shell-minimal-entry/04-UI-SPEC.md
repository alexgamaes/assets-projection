# Phase 4 — UI Design Contract

> Visual and interaction contract for Phase 4 (UI Shell & Minimal Entry). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 4 replaces the Phase 3 dev-harness chrome with a **real, responsive 2-input entry shell** around the already-proven engine + selectors + three ECharts charts. It is **additive UI wiring**, not a redesign: the Phase 3 UI-SPEC (`.planning/phases/03-selectors-visualization-neutrality-style-guide/03-UI-SPEC.md`, status `approved`) remains the **binding base contract**. This document extends it with the **control panel, responsive layout, summary readout, real/nominal toggle, and the new copy surfaces** introduced by ENTRY-01..ENTRY-06. Where this spec is silent, the Phase 3 contract governs (typography, spacing, palette, card treatment, ECharts `textStyle`, all three chart/tooltip contracts, citation footer).

**Neutrality remains the dominant visual constraint** (PROJECT.md). All new copy is seeded into `docs/NEUTRALITY-STYLE-GUIDE.md` and gated by Phase 5 (NEUT-02) — no semantic red/green, no value-laden copy, no axis tricks, no zero-sum framing.

## Spacing Scale

Inherited verbatim from the Phase 3 contract (Tailwind v4 default 4px base). No new tokens, no exceptions beyond the touch-target rule below.

| Token | Value | Usage (Phase 4 additions in **bold**) |
|-------|-------|---------------------------------------|
| xs | 4px | Inline gaps (slider ↔ label, toggle label ↔ control) |
| sm | 8px | **Label ↔ slider gap; numeric-field ↔ slider gap within a control row**; footer citation line spacing |
| md | 16px | **Control panel inner padding; gap between stacked control rows**; chart card inner padding |
| lg | 24px | Gap between the three stacked charts; **control-panel ↔ chart-column gap (desktop grid `gap`)**; section padding |
| xl | 32px | Page content vertical rhythm; **control panel ↔ summary readout vertical gap on mobile stack** |
| 2xl | 48px | Major break above the citation footer |
| 3xl | 64px | Page top/bottom outer margin (desktop) |

Exceptions: **Interactive control hit targets (slider thumb, numeric field, toggle segments) must be ≥ 44px in the touch dimension** (WCAG 2.5.5 / iOS HIG, required by ENTRY-06 touch-graceful). The 44px applies to the *rendered control's tappable area* only; all surrounding layout spacing stays on the 4px scale. ECharts internal `grid`/`padding` values stay multiples of 4 (Phase 3 rule, unchanged).

## Typography

Inherited verbatim from the Phase 3 contract: **exactly 4 sizes, exactly 2 weights (400 regular, 600 semibold). No italic, no other weights, no new sizes.**

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Display | 28px | 600 | 1.2 |
| Heading | 20px | 600 | 1.2 |
| Body | 16px | 400 | 1.5 |
| Label | 14px | 400 | 1.5 |

Phase 4 mapping (in addition to the Phase 3 chart mappings, which are unchanged):

- **Display 28/600** — the single page title only (replaces the Phase 3 harness title). One instance.
- **Heading 20/600** — each chart's neutral title (3 instances, unchanged from Phase 3); the **summary readout section heading** (one instance, e.g. `"Summary"`); the control-panel section heading if one is rendered.
- **Body 16/400** — the log/linear scale-explanatory copy (Phase 3, unchanged); the **nominal money-illusion caption (D-09)**; the **rank-delta neutral disclosure (D-15)**; the relative-position caption (Phase 3, unchanged).
- **Label 14/400** — control labels ("Current wealth", "Annual savings", "Projection horizon"), slider/field current-value readouts, toggle segment text, **summary metric labels** ("Ending wealth", "Growth multiple", "CAGR", rank-delta label), chart axis/legend/tooltip text (Phase 3, unchanged). Tabular numerals enforced on every value.

The three **summary metric values** (ending wealth, growth multiple, CAGR) are emphasized **by weight only (600 semibold) at Body 16px**, never by introducing a new size, color, or the accent hue. The numeric magnitude is the focus; do not visually shout it.

ECharts `textStyle` stays at the Phase 3 exact sizes/weights (do not accept ECharts default 12px).

## Color

Inherited verbatim from the Phase 3 neutral, value-free palette. **No red/green anywhere. No new hues.** The accent is strictly rationed; controls are chrome, not accent surfaces.

| Role | Value | Usage (Phase 4 scope) |
|------|-------|----------------------|
| Dominant (60%) | `#FFFFFF` (page) / `#F8FAFC` slate-50 (card/panel surface) | Page background, control-panel surface, chart card surfaces, summary readout surface, whitespace |
| Secondary (30%) | `#475569` slate-600 (text) / `#E2E8F0` slate-200 (borders) | Control labels, metric labels, metric values, slider tracks, numeric-field borders, panel/card borders, gridlines, axis lines |
| Accent (10%) | `#0F766E` teal-700 | **Strictly: (1) the user's own series line in all three charts; (2) the active segment of the log/linear toggle; (3) the active segment of the real/nominal toggle; (4) the slider filled-track + thumb and the numeric-field focus ring.** Nothing else. |
| Destructive | not used | No destructive actions exist in this phase (see Copywriting Contract) |

Accent reserved for — explicit, exhaustive list (never "all interactive elements"):
1. User trajectory line/series across all three charts (Phase 3, unchanged).
2. Active segment of the log/linear toggle (Phase 3, unchanged).
3. Active segment of the real/nominal toggle (new — mirrors #2's treatment exactly).
4. Slider filled portion + thumb, and the focus ring of the numeric input fields (new — the affordance that says "this is the live control you're playing with"; reinforces the play→watch loop without adding a hue).

**Hard constraint:** the accent must **never** encode that a number is good/bad/up/down. It does not change when wealth rises or rank falls. The real/nominal toggle's accent indicates *which segment is selected*, never which is "better" — real is the honest default but is not visually privileged over nominal beyond being the default-selected segment. The tier-series categorical palette (median/top10/top1/top0.1, threshold bands) is inherited unchanged from the Phase 3 table.

## Copywriting Contract

Phase 4 introduces the project's **first real user-facing controls and the first error/empty considerations**. Every string below is **new neutral copy** and MUST be seeded into `docs/NEUTRALITY-STYLE-GUIDE.md` (extending the Phase 3 lexicon/section pattern) so Phase 5 NEUT-02 gates it verbatim. Exact final wording is authored against the style guide; templates below are neutral and prescriptive.

| Element | Copy |
|---------|------|
| Primary CTA | **None — by design (ENTRY-01).** There is no "Calculate"/"Run"/"Project" button anywhere. The projection is a derived value rendered on first paint and live-recomputed on input change. Introducing any submit/trigger control is a contract violation. |
| Empty state heading | Not applicable — the chart surface is **never empty**: it renders on first paint from cited median seed defaults (D-02) before any interaction. There is no zero-data state to design copy for. |
| Empty state body | Not applicable (same reason). |
| Error state | Two cases: (a) **Out-of-range / malformed typed input** — handled at the field boundary by clamp/Zod (no engine call with NaN/negative); the field shows a single neutral Label-14 helper line, no alarm punctuation, e.g. `"Enter an amount of 0 or more."` and the projection continues from the last valid value (never blanks the charts). (b) **Engine throw** (basis violation / malformed params — should not occur with guarded inputs) — reuse the Phase 3 neutral diagnostic line verbatim: `"Projection unavailable: the model could not produce a result from the current parameters."` No styled error UI, no stack trace, no remediation CTA. |
| Destructive confirmation | Not applicable — **no destructive actions exist in this phase.** Adjusting a slider/field/toggle is non-destructive and instantly reversible; there is no delete, reset-to-default, clear, or data-loss action in Phase 4 scope (reset-to-defaults is v2 CONFIG-03, explicitly out of scope). No confirmation dialogs. |

**New neutral copy surfaces (all style-guide-governed, factual, no blame/virtue, no alarm punctuation):**

| Surface | Required copy intent (final wording authored against the style guide; neutral templates below) |
|---------|------|
| Page title | Plain descriptor, no editorializing (replaces Phase 3 harness title). Template: `"Wealth projection"` (optionally with a neutral subtitle stating it uses heterogeneous, source-cited returns — no value framing). |
| Current-wealth control label | `"Current wealth"` (Label 14/400). Neutral unit hint allowed: `"Today's money (USD)"`. |
| Annual-savings control label | `"Annual savings"`. Same neutral unit hint pattern. |
| Horizon control label + live readout | `"Projection horizon"` with a live year readout, e.g. `"35 years"`. No "only"/"already"/"just" qualifiers. |
| Real/nominal toggle | Two segments labelled `"Real"` and `"Nominal"`, default `"Real"`. A scoping Label-14 line: `"Real adjusts for inflation; nominal does not."` — strictly factual, neither described as better. |
| Money-illusion caption (D-09, shown only when Nominal is active) | Fixed neutral caption (Body 16/400) directly adjacent to the affected money surfaces, stating the figures are **not** inflation-adjusted and citing the inflation rate + source used. Template: `"These figures are not adjusted for inflation. They assume a fixed [X]% annual inflation rate (source: [SourceRecord.sourceName]). Switch to Real for inflation-adjusted amounts."` Wording + the cited rate are **seeded into `docs/NEUTRALITY-STYLE-GUIDE.md`** (mirrors the Phase 3 D-11 caption pattern) for the Phase 5 gate. Mandatory whenever `basis === 'nominal'`; absent when `'real'`. |
| Summary readout labels (D-13) | Three required metrics, neutral noun labels, basis-tracking: `"Ending wealth"`, `"Growth multiple"` (e.g. `"6.2×"`), `"CAGR"` (e.g. `"3.1% / yr"`). When nominal is active the money labels carry a neutral `"(nominal)"` qualifier; real shows `"(real)"` or no qualifier (real is default/honest). |
| Rank-delta stat (D-14) | Always rendered as a **delta paired with same-horizon wealth growth**, never a bare absolute. Template: `"Distribution position: p[NN] → p[MM] over [Y] years, while real wealth grew [G]×."` The wealth-growth clause is **mandatory and adjacent** — the rank figure must never appear without it (Pitfall 4 / zero-sum misread). |
| Rank-delta neutral disclosure (D-15) | A fixed neutral sentence (Body 16/400) accompanying the rank-delta stat, stating rank can shift while real wealth still grows for every tier. Template: `"Rank can move down while real wealth still grows — every tier's wealth increases over this horizon. See the wealth-by-tier chart for absolute amounts."` Wording **seeded into `docs/NEUTRALITY-STYLE-GUIDE.md`** for the Phase 5 gate. The rank-delta stat is **never shown in isolation** from this disclosure. |
| Citation footer (VIZ-06) | Phase 3 footer line, unchanged, **plus** the two new cited defaults (seed median net worth + inflation rate) appended to the same neutral source line via their `SourceRecord` entries. No editorial framing. |

**Banned in all of the above (Phase 3 style-guide lexicon, carried forward):** value-laden adjectives/verbs ("soar", "plummet", "trapped", "winners", "losers", "unfair", "elite", "only", "just" as minimizers), alarm punctuation ("!"), blame/virtue framing, zero-sum / finite-pie language. The rank-delta and nominal-caption surfaces carry the strictest scrutiny (Pitfall 4 / Pitfall 5).

## Interaction & Control Contract

Prescriptive contract for the executor. Phase 4 adds **controls and layout only**; the three chart contracts, the shared log/linear toggle contract, the combined-tooltip (D-08) and rank-paired-with-wealth tooltip (D-11) safeguards, and the citation-footer contract are **inherited unchanged from the Phase 3 UI-SPEC and must continue to hold**, including on touch.

### Layout (D-10 / D-11 / ENTRY-06)

- **Mobile-first single column.** Order top→bottom: page title → **control panel (full-width block)** → summary readout → Chart 1 → Chart 2 → Chart 3 → citation footer. No hidden UI, no bottom sheet, no accordion (D-11). The Phase 3 single-column stacked-chart order is preserved.
- **Desktop:** at the Tailwind **`lg` (1024px) breakpoint** switch to a two-column grid: `lg:grid lg:grid-cols-[320px_1fr] lg:gap-8` (24px `lg` gap). Left column = a **`lg:sticky lg:top-8 lg:self-start` control panel** holding all controls (2 inputs + horizon + log/linear toggle + real/nominal toggle); right column = the three stacked charts + summary readout + footer scrolling beside it. Controls stay reachable while exploring (the play→watch loop). Rationale for `lg` not `md`: a 320px control column + a ≥320px chart need ≥1024px to coexist without crushing either; below that, stack.
- Page max width and outer margins follow the Phase 3 contract (`max-w-6xl`, `3xl` outer margin desktop). Control-panel surface uses the **Phase 3 card treatment verbatim**: `#F8FAFC` surface, 1px `#E2E8F0` border, `md` 16px inner padding, rounded, no importance-implying shadow.
- **Chart minimum height 320px each is unchanged** (Phase 3 contract). On small screens charts remain ≥320px and full content width; do not shrink below 320px (legibility of multi-decade compounding). Equal card treatment between the three charts (no visual hierarchy) is unchanged.
- **Summary readout placement:** placed at the **top of the chart column** (immediately under the control panel on mobile; top of the right column on desktop) so cause→effect (control change → metric change) is visible in one glance without scrolling. Placement was Claude's-discretion (CONTEXT); the three metrics, basis-tracking (D-13), and rank-delta treatment (D-14/D-15) are locked.

### Primary inputs — log slider ⇄ numeric field (D-01 / D-02 / D-04)

- Two controls, **identical pattern**: current wealth, annual savings. Each is a **logarithmic range slider linked to a numeric field** sharing one value. Drag slider = play fast (feeds the debounced recompute); type in field = precision.
- Slider operates in `log10` space (D-04) so the low end stays usable. Span is broad and grounded in `src/data/defaults.ts` tier boundaries (planner finalizes exact min/max/step): annual savings ≈ `$2k → $2M/yr`; current wealth similarly broad spanning median → top-tier magnitudes.
- The **numeric field accepts values outside the slider span** (D-04); the slider thumb clamps to `[min,max]` but the stored value is whatever was typed. Boundary guard (clamp or Zod, planner's discretion) ensures the engine never receives `NaN`, negative, or non-finite values — on a bad value, fall back to the last valid value and show the neutral helper line (see Error state); never blank the charts.
- **Default seed values are cited rounded-up real-world medians (D-02/D-03):** current wealth ≈ `$200,000` (rounds up 2022 SCF median family net worth `$192,900`); annual savings ≈ a rounded-up median savings figure. Both carry a full six-field `SourceRecord` in `src/data/sources.ts` (Phase 2 pattern, self-describing as a UX default) and surface through the existing citation footer (VIZ-06).
- Slider thumb + numeric field hit target ≥ 44px in the touch dimension. Field uses `inputMode="numeric"`. Each control: Label 14/400 label above, value visible at all times (tabular-nums).

### Horizon control (D-05 / ENTRY-03)

- A **linear range slider** (not log) with a **live year readout** (Label 14/400, e.g. `"35 years"`). Default ≈ **35y**, range ≈ **10–60y** (engine supports ≤60). Continuous drag updates the readout live; recompute is debounced like the other sliders. ≥44px touch target.

### Real / nominal toggle (D-06 / D-08 / ENTRY-04)

- A **two-segment segmented control** (`Real` | `Nominal`), **default `Real`**, styled to **mirror the Phase 3 log/linear toggle exactly** (active segment accent `#0F766E`; inactive = Secondary text on Dominant surface; keyboard-focusable; `role` + `aria-pressed` on segments).
- Switching to `Nominal` re-inflates **all money surfaces consistently** — Chart 1, Chart 2, and the summary readout's money metrics — via the **display-layer re-inflation selector only** (engine stays real-only; D-06). Chart 3 (rank/percentile) and the rank-delta stat are **unitless and unaffected** (D-08).
- When `Nominal` is active, the **money-illusion caption (D-09)** is mandatory and visible adjacent to the affected surfaces; it disappears when `Real` is active. The toggle never implies one basis is "better".

### Live recompute & no-jank (ENTRY-01 / ENTRY-02)

- **No Calculate gate.** Projection renders on first paint from store defaults; every control change recomputes live. Slider drag is debounced via React 19 `useDeferredValue` (recompute is synchronous & sub-ms; no timer/magic-ms) — slider thumb stays responsive, charts/metrics update without jank. Typed-field commit recomputes on change/blur. Mechanism is planner's discretion; the *contract* is: first-paint render, live update, smooth drag, no submit affordance.

### Touch interaction (D-12 / ENTRY-06)

- All controls operable by touch: ≥44px targets, native `range`/`number` inputs (no custom gesture code), toggles are tappable segments.
- **Every Phase 3 chart tooltip safeguard must continue to work on touch — never hover-only.** Specifically: the D-08 combined divergence tooltip and the D-11 rank-paired-with-real-wealth tooltip must trigger on tap and dismiss on tap-away (ECharts 6 default with the Phase 3 `trigger:'axis', confine:true` config). **Do not** set `triggerOn:'mousemove'` (it disables tap). No new chart components — reuse the Phase 3 `notMerge` wrappers verbatim so basis/scale toggles don't leave stale axes.

### Accessibility (ENTRY-06 baseline)

- All controls keyboard-operable (sliders arrow-key adjustable, fields tab-focusable, toggle segments focusable with visible focus ring in accent). Every control has a programmatic label (the visible Label-14 text via `<label>`/`aria-label`). Toggle segments expose `aria-pressed`. Focus ring uses the accent hue (the only added accent use #4); contrast of Secondary text `#475569` on Dominant `#FFFFFF`/`#F8FAFC` meets WCAG AA (carried from Phase 3).
