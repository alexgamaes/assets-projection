# Phase 4.1 — UI Design Contract

> Visual and interaction contract for VIZ-07 (Tier Share-of-Economy Visualization).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> This phase composes TWO new ECharts components into the existing AppShell. The
> codebase has locked Phase 3/4 conventions and a deliberate "no design system"
> decision (CLAUDE.md). This contract LOCKS the residual visual/interaction
> decisions CONTEXT.md left to Claude's discretion. It does NOT override any
> locked decision (D-01..D-12, D-16) or the NEUTRALITY-STYLE-GUIDE.

## Color

No new hue. Reuse `COLORS` constants from `src/state/selectors.ts` verbatim
(D-04, NEUTRALITY-STYLE-GUIDE §4 Palette Clause). No semantic red/green.

### Surface (inherited, unchanged)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` (page) / `slate-50` `#F8FAFC` (section fill) | Page background + the two new section cards (`bg-slate-50`) |
| Secondary (30%) | `slate-200` `#E2E8F0` | Section borders (`border-slate-200`) |
| Accent (10%) | `COLORS.user` teal-700 `#0F766E` | RESERVED: user-position line on the stacked-area chart + "You" end-label ONLY |
| Destructive | none | No destructive actions in this phase |

Accent reserved for: the user-position findability cue ONLY (the dashed
user line + its "You" `endLabel` on the stacked-area chart). Per
NEUTRALITY-STYLE-GUIDE §4, teal-700 is a neutral findability accent, NOT a value
signal. It carries no evaluative meaning. No other element may use it.

### Band hue↔band assignment (LOCKED — resolves D-04 planner discretion)

Chosen to maximize categorical contrast between vertically-adjacent stacked
bands while reusing only the 5 existing palette constants. Each band gets a
distinct existing hue; no hue implies rank/virtue (NEUTRALITY-STYLE-GUIDE §4).

| Band (D-02) | Hue constant | Hex | Rationale |
|-------------|--------------|-----|-----------|
| Bottom 50% | `COLORS.median` | `#64748B` slate-500 | Base of stack (D-09); the most neutral/desaturated hue anchors the largest visual mass |
| 50–90% | `COLORS.top10` | `#7C3AED` violet-600 | High contrast vs adjacent slate below |
| 90–99% | `COLORS.top1` | `#2563EB` blue-600 | High contrast vs adjacent violet below |
| 99–99.9% | `COLORS.top01` | `#0891B2` cyan-600 | High contrast vs adjacent blue below |
| Top 0.1% | `COLORS.user` | `#0F766E` teal-700 | Caps the stack (D-09) |

> **Color-collision note (binding for the planner):** On the stacked-area chart
> the user-position LINE uses `COLORS.user` (teal-700) and the Top-0.1% BAND also
> uses `COLORS.user`. They never visually collide in practice (the line is a thin
> 3.5px dashed stroke on a hidden axis; the band is a filled area), AND this reuse
> is mandated by D-04 (only 5 existing hues, 5 bands + 1 user = 6 needs). To keep
> them distinguishable the planner MUST: (a) render the user line **dashed**
> (`lineStyle.type: 'dashed'`, width 3.5 — matches RESEARCH Pattern 3) while all
> band fills are solid `areaStyle`, and (b) give the user line an opaque stroke
> while band `areaStyle` may use ECharts' default fill (lower alpha). The "You"
> `endLabel` disambiguates further. This is the neutrality-safe resolution; do
> NOT introduce a 6th hue to avoid the collision (that would violate D-04 / §4).

### Donut "your band" highlight (LOCKED — resolves D-07)

The user's final-year band is highlighted with a **neutral outline only**, never
a pop-out, never red/green, never a saturation change:

- `data[userBandIdx].itemStyle.borderColor = '#1E293B'` (slate-800 — neutral, in
  the existing slate family, carries no valence)
- `data[userBandIdx].itemStyle.borderWidth = 3`
- `data[userBandIdx].label.fontWeight = 600` (the only typographic emphasis)
- Do NOT use `selected: true` / pop-out (RESEARCH Pitfall 4 — also reads as
  evaluative). Do NOT recolor the slice.

### Caption placement (LOCKED — resolves RESEARCH Open Q 1 & 2)

- **One caption per chart** (not a single shared caption between them). Mirrors
  the D-15 per-chart enforcement model and gives Phase 5 a deterministic DOM
  target per section. The two captions are byte-identical strings.
- **Caption rendered by the chart component as a `caption` prop**, NOT by
  AppShell inline. `TierShareChart` and `DonutChart` accept `caption: string`
  and render it as a `<p className="text-base font-normal text-slate-600 mt-2">`
  beneath the canvas — exactly mirroring `RelativePosChart`'s existing
  caption-as-prop contract. Rationale: the caption is structural to the chart
  (mandatory disclosure), not optional chrome; this matches D-15's enforcement
  model and keeps the Phase 5 check co-located with the component.
- The D-11 basis-inert note is rendered by AppShell directly under each chart
  section (it is a basis/toggle clarification about app state, not chart-
  structural), as `<p className="text-sm font-normal text-slate-500 mt-1">`.
- DOM order inside each `<section>`: `<h2>` → chart canvas → D-11 note (`mt-1`,
  14px slate-500) → D-16 caption (`mt-2`, 16px slate-600). The D-16 caption is
  visually heavier than the D-11 note — correct, the disclosure outranks the
  technical note.

### Responsive / layout placement (LOCKED — resolves CONTEXT discretion item)

- Both new sections are appended **after Chart 3** (relative-position) and
  **before** `<CitationFooter>`, inside the existing `<main className="space-y-6">`
  `rawResult !== null` branch. Order: …Chart 3 → **Stacked-area (Chart 4)** →
  **Donut (Chart 5)** → CitationFooter.
- Rationale: the D-16 caption references "the wealth-by-tier chart above"
  (Chart 2). Placing these after Charts 1–3 keeps that backward reference valid
  and preserves the narrative arc (levels → divergence → rank → composition).
- Each section is a full-width block in the existing single-column `<main>`
  (the 320px control panel + `1fr` grid already handles desktop/mobile;
  `space-y-6` provides the 24px vertical rhythm). No new breakpoints. On mobile
  the sections stack in the same DOM order (stacked-area then donut) — no
  reordering, no horizontal scroll; ECharts `width: '100%'` + 320px height is
  the established touch-degradation pattern (ENTRY-06 / Phase 4 D-12).
- Tooltips: `trigger: 'axis'` + `confine: true` for the stacked-area (matches
  existing charts); `trigger: 'item'` for the donut. `confine: true` keeps
  tooltips inside the canvas on touch (Phase 3 touch convention).
