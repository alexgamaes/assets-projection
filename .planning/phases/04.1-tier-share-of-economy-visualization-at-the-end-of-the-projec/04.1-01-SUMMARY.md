# Phase 4.1 Plan 01: VIZ-07 Engine Foundation Summary

One-liner: Pure `deriveBandShares` function + Wave-0 tests delivering five-band Lorenz wealth-mass fractions (D-01/D-02) from the projection series, with calibration-error fallback and D-12 basis-invariance verification.

## What Was Built

**`src/core/tierBands.ts`** — framework-free pure module exporting:
- `interface BandShare` — five fixed population-fraction bands per year: `bottom50`, `band50to90`, `band90to99`, `band99to999`, `top01`
- `function deriveBandShares(series: YearSnapshot[]): BandShare[]` — maps the projection series to per-year Lorenz mass fractions that sum to 1.0 (D-01), using the five fixed boundaries [0,0.5), [0.5,0.9), [0.9,0.99), [0.99,0.999), [0.999,1] (D-02)

**`src/core/__tests__/tierBands.test.ts`** — 12 tests covering:
- **Test A (D-01 band-sum):** every BandShare sums within DIST_TOL of 1.0 over a 60-year projection
- **Test B (D-02 Pareto fixture):** pure-Pareto(alpha=2) closed-form `sqrt(1-p)` values verified; self-consistency test (deriveBandShares matches independent cumulativeShareFromTop computation); D-02 boundary reference values asserted
- **Test C (D-12 basis-invariance):** year-0 toEqual (factor=1 exactly); years 1+ within DIST_TOL
- **Test D (T-04.1-01 fallback):** no-throw, no-NaN, degenerate=0.2 at year-0, carry-forward for subsequent years

## Key Implementation Details

**Band math formula (per-year):**
```
s50  = cumulativeShareFromTop(curve, 0.5)
s90  = cumulativeShareFromTop(curve, 0.9)
s99  = cumulativeShareFromTop(curve, 0.99)
s999 = cumulativeShareFromTop(curve, 0.999)
bottom50    = 1 - s50
band50to90  = s50 - s90
band90to99  = s90 - s99
band99to999 = s99 - s999
top01       = s999
normalize: total = sum; f = total > 0 ? 1/total : 1
```

**Fallback (T-04.1-01):**
- Year-0 calibration failure → degenerate uniform entry (all five bands = 0.2)
- Year 1+ failure → carry forward previous year's BandShare (year field updated)
- No error ever propagates out of `deriveBandShares`

**Boundary decision honored:** zero imports from `./engine.js` — `anchorWealthToAnchors` and `shiftScaleCurve` are private. Anchors are constructed locally from `snap.anchorWealth` values.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Pareto(alpha=2) fixture: calibration fails for requested anchors**

- **Found during:** Task 2 implementation
- **Issue:** The plan suggested using anchors with `top01/top1 = sqrt(10)` to produce alpha=2 and `median=1, top10=2` (or SYNTH_ANCHORS median/top10 with `top1=2M, top01=2M*sqrt(10)`). Both fail the bisection bracket check: with alpha=2, the stitch root falls outside [0.9001, 0.9999]. Root analysis: at qs=0.9999, `Q_ln(qs) * sqrt(0.01) ≈ 910k < top1=2M` → both endpoints have same sign → CR-01 fires.
- **Fix:** Redesigned Test B to use three complementary tests: (a) verify pure-Pareto closed-form values directly (`sqrt(1-p)` identity); (b) self-consistency test — compute expected bands via `cumulativeShareFromTop` independently and assert `deriveBandShares` matches within DIST_TOL; (c) reference value assertions for the five Pareto(alpha=2) band values. The plan's "OR" clause (internal seam / direct math verification) was applied.
- **Mathematical integrity preserved:** The pure-Pareto formula `cumulativeShareFromTop(curve, p) = sqrt(1-p)` for Pareto(alpha=2) is still verified through the reference values test (test `'Pareto fixture bands (pure closed-form)'`).
- **Files modified:** `src/core/__tests__/tierBands.test.ts`
- **Commit:** a374998

**2. [Rule 1 - Bug] D-12 basis-invariance: floating-point rounding under nominal re-inflation**

- **Found during:** Task 2 implementation
- **Issue:** The plan specified `expect(real).toEqual(nominal)` (strict deep equality). `selectReinflated` multiplies `anchorWealth` by `(1+i)^year`, introducing ~1e-15 FP differences in year 1+ (because IEEE-754 multiplication by a non-integer factor is not exactly reversible). The mathematical property is approximately true (Lorenz fractions are scale-invariant), but not bit-for-bit identical after FP scaling.
- **Fix:** Year-0 uses `toEqual` (factor = `(1+0.025)^0 = 1.0` exactly → bit-for-bit identical). Years 1+ use per-field `toBeLessThan(DIST_TOL)` comparison. This correctly reflects the mathematical intent while being honest about FP behavior.
- **Files modified:** `src/core/__tests__/tierBands.test.ts`
- **Commit:** a374998
