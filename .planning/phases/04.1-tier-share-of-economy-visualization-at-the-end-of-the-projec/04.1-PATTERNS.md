### `src/core/tierBands.ts` (model, transform) — NEW

**Analog:** `src/core/relativePosition.ts` (the `deriveShares` precedent — pure `YearSnapshot[]` → derived series).

**Imports pattern** (`relativePosition.ts` lines 22, and `distribution.ts` exports):
```typescript
import type { YearSnapshot } from './types.js';

```
Note `.js` extension on relative imports is the project convention (ESM/NodeNext) — `relativePosition.ts:22` uses `'./types.js'`.

**Core transform pattern — mirror `deriveShares` shape** (`relativePosition.ts` lines 44-64):
```typescript
export function deriveShares(
  series: YearSnapshot[],
): Array<{ year: number; userShare: number; userRank: number }> {
  return series.map((snap) => {
    const totalWealth = (snap as YearSnapshot & { _totalWealth?: number })._totalWealth;
    const denominator = totalWealth ?? snap.anchorWealth.top01;
    const userShare = denominator > 0 ? snap.userWealth / denominator : 0;
    return { year: snap.year, userShare, userRank: snap.userPercentile * 100 };
  });
}
```
`deriveBandShares` follows the same `series.map(snap => …)` pure structure, returning a `BandShare[]` (the typed-result-array convention; see CLAUDE.md "model code returns typed result series").

**Curve reconstruction (Pattern 1 / Option A) — the key extension over `deriveShares`:**
`deriveShares` only needs `_totalWealth` (a scalar already on the snapshot). `deriveBandShares` needs the full `Curve` for partial integrals, so it must rebuild the curve per year via `calibrateCurve`. **`calibrateCurve` takes `Anchors` (SourcedParam-valued), not raw numbers** — see signature below. The engine's `anchorWealthToAnchors` helper that does this conversion is **private (not exported)** from `engine.ts:166`, so `tierBands.ts` must either (a) build a minimal `Anchors` object from `snap.anchorWealth` using a local `synParam`-like wrapper, or (b) export `anchorWealthToAnchors` from `engine.ts`. The planner decides; (a) keeps `tierBands.ts` decoupled from `engine.ts`.

`calibrateCurve` signature (`distribution.ts:286`):
```typescript
export function calibrateCurve(anchors: Anchors): Curve
// Anchors = { median: SourcedParam; top10: SourcedParam; top1: SourcedParam; top01: SourcedParam }
// reads anchors.median.value, anchors.top10.value, anchors.top1.value, anchors.top01.value
```

`Curve` shape (`distribution.ts:56-66`): `{ lognormal:{mu,sigma}, pareto:{alpha,xm}, stitchQuantile, totalWealth }`.

`cumulativeShareFromTop` signature (`distribution.ts:468`, returns share ∈ [0,1] held by top (1-p)):
```typescript
export function cumulativeShareFromTop(curve: Curve, p: number): number
// p<=0 → 1 ; p>=1 → 0 ; closed-form lognormal+Pareto
```

**Calibration-fallback mirroring (Pitfall 2) — copy the engine's exact try/catch idiom** (`engine.ts:274-284`):
```typescript
try {
  nextCurve = calibrateCurve(anchorWealthToAnchors(newAnchorWealth, params));
} catch {
  nextCurve = shiftScaleCurve(curve, anchorWealth, newAnchorWealth);
}
```
`deriveBandShares` must wrap its per-year `calibrateCurve` in the same `try/catch`. `shiftScaleCurve` is a **private** function in `engine.ts:134` (not exported) — for the selector layer, the simplest mirror is: on calibration failure, fall back to the prior year's `BandShare` (or a null entry that the AppShell null-guard suppresses), since `shiftScaleCurve` is not reachable from `core/tierBands.ts` without an export change.

**Float-sum normalization (Pitfall 3):** after the five `cumulativeShareFromTop` differences, divide each by their sum so they total exactly 1.0. RESEARCH §"Code Examples" gives the exact sketch (lines 568-595).
