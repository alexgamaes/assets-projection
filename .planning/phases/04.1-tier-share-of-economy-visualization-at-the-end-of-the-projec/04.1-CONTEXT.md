# Phase 4.1: Tier Share-of-Economy Visualization - Context

**Gathered:** 2026-05-16
**Status:** Ready for planning

<domain>
## Phase Boundary

Deliver VIZ-07: a tier share-of-economy view composed into AppShell, consisting of
(a) a 100%-stacked-area chart of each population band's share of total distribution
wealth across every horizon year, and (b) an end-of-horizon donut of the same split.
Reuses the existing categorical palette (no semantic red/green, no new hue, D-03) and
carries a mandatory neutral no-zero-sum caption governed by a new style-guide rule
(D-16) that Phase 5 NEUT-02 will gate.

In scope: per-band wealth-mass + share-of-total computation (engine/selector layer),
the two new chart components, the user-position overlay, the D-16 style-guide rule +
verbatim caption, and basis-invariance handling/tests.

Out of scope: new model parameters, changes to existing charts, Monte Carlo, URL
state sharing, scenario comparison.

</domain>

<decisions>
## Implementation Decisions

### Slice definition (what the chart shows)
- **D-01:** Slices are **Lorenz population-mass bands** — total wealth *held by* each
  population segment, integrated from the calibrated lognormal+Pareto curve, summing
  to exactly 100% of total distribution wealth per year. NOT normalized anchor point
  values, NOT a 2-slice top-set split.
- **D-02:** Five fixed bands by population fraction: **Bottom 50%, 50–90%, 90–99%,
  99–99.9%, Top 0.1%** (boundaries align with the existing p50/p90/p99/p99.9 anchors).
- **D-03:** Bands are labeled as **population ranges** ("Bottom 50%", "50–90%", …),
  not the "median / top 10%" point vocabulary used by the other charts — because a
  band is a mass over a range, not a single anchor point. Accuracy over cross-chart
  label consistency.
- **D-04:** Bands use the **existing categorical palette** (the 5 hues already used
  for user + median/top10/top1/top01). No new hue, no semantic red/green (VIZ-07/D-03
  Palette Clause). Hue↔band mapping is the planner's discretion as long as it reuses
  existing palette constants.

### User representation
- **D-05:** **No user slice.** The user is one household (~0% of total) and is already
  contained within whichever population band their percentile falls in — a literal
  slice would double-count and be invisible.
- **D-06:** On the **stacked-area** chart, the user's position is a line traced across
  **every horizon year**, derived from per-year `userPercentile` mapped onto the
  cumulative-share axis — so the viewer sees the user drift across bands over time
  (ties to the project's "watch relative position shift" thesis).
- **D-07:** On the **donut** (final-year snapshot), the band the user falls into at the
  final year is visually highlighted/outlined as "your band".

### Donut center + band order
- **D-08:** Donut **center label = top-set concentration**, reusing the existing
  `topSetPercentile`: states "Top X% hold ≥50% of total wealth (year N)" (neutral,
  factual, the concentration the project is about).
- **D-09:** **Band stacking order: poorest at bottom** — Bottom 50% at the base of the
  stacked area (and clockwise-from-12 on the donut), Top 0.1% on top. Conventional
  concentration reading; the growing top bands visually cap the chart.

### Caption + basis behavior
- **D-10:** Add a **new D-16 rule** to `docs/NEUTRALITY-STYLE-GUIDE.md` (new section,
  next id after D-15) governing the share-of-economy disclosure: a **verbatim caption
  template** with a no-zero-sum clause clarifying *shares can shift while every band's
  real wealth still grows* — i.e. a falling share does not mean falling wealth. Phase 5
  NEUT-02 checks the rendered caption text equals the template (same enforcement model
  as D-15). The caption is mandatory and rendered as a visible DOM element on/near both
  charts (not tooltip-only), consistent with the D-15 disclosure pattern.
- **D-11:** The real/nominal toggle stays **visible but inert** for these two charts
  (it is the shared global toggle used by other charts) and a **short neutral note**
  states shares are identical in real and nominal terms (basis-invariant). Not silently
  inert, not hidden.
- **D-12:** Basis-invariance is **asserted in tests**: the share series / donut data
  must be byte-identical under real vs nominal basis.

### Claude's Discretion
- Exact placement of the two new charts within the AppShell layout and their
  mobile/responsive stacking order (follow existing AppShell responsive patterns).
- Donut interactivity/tooltip details and stacked-area hover tooltip content, within
  the existing D-12-touch and tooltip conventions established in Phase 3.
- Hue↔band assignment within the existing palette.
- Degenerate/empty-curve handling — follow the existing AppShell engine-error
  containment pattern (neutral diagnostic string, no stack trace).

</decisions>

### Reusable Assets
- `src/state/selectors.ts` `COLORS` constants — the 5-hue categorical palette to reuse for the bands (D-04).
- Existing ECharts selector pattern (`selectTimeSeriesOption`/`selectDivergenceOption`/`selectRelPosOption`) — the new stacked-area + donut option builders follow the same memoized `params → model → ECharts option` shape.
- `topSetPercentile` (already in `YearSnapshot`) — directly feeds the donut center label (D-08); no new computation needed for that piece.
- `userPercentile` per year (already in `YearSnapshot`) — feeds the user-position trace (D-06); no new computation needed.
- AppShell's `useDeferredValue + try/catch useMemo + neutral diagnostic` pattern — reuse for the new charts' error/empty handling.
- D-15 disclosure implementation (caption as visible DOM element, verbatim template, Phase 5 text-equality) — structural template for D-16.

### Established Patterns
- Pure framework-free model/selector code, unit-tested with Vitest fixtures; correctness-first (`tsc --noEmit` clean, full suite green) — the per-band mass integration must be a pure tested function with known fixtures.
- Neutrality is a hard release gate (Phase 5 NEUT-02); palette/caption decisions are contractually constrained, not stylistic.

### Integration Points
- New per-band share data: extend `ProjectionResult` (or a derived selector) — today only `userShare`/`topSetPercentile` exist, no per-band mass series.
- New chart components composed into `src/ui/AppShell.tsx` alongside the existing three charts.
- New D-16 rule appended to `docs/NEUTRALITY-STYLE-GUIDE.md`.

<specifics>
## Specific Ideas

- Stacked-area: 100%-normalized bands, poorest at bottom, user position as a line drifting across bands over the full horizon.
- Donut: final-year snapshot, same band order clockwise from 12, center label "Top X% hold ≥50% of total wealth (year N)", user's band outlined.
- Basis note (neutral): shares are identical in real and nominal terms; the real/nominal toggle does not affect this view.
